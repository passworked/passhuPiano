# 播放控制与用户界面

## 2026-11-01 提琴独立奏法

乐器弹层在小提琴、中提琴、大提琴、低音提琴各自行的右侧显示奏法按钮，左侧仍是勾选及琴名；未勾选时奏法按钮禁用，不另占底部空间。各自可选自动、长弓、跳弓、拨弦。自动沿用原 Program 判断；显式目标的手动输入自动模式使用既有默认奏法。手动选择优先于 Program，影响文件、硬件 / 手动实时输入和运弓。选择后只关闭奏法列表，保留乐器弹层；取消某把提琴后保留它的选择，重新启用时恢复。选项属于公共状态，按现有权限及网络流程提交。暂停中更改不发声、不改进度；播放中仅更换对应提琴的活动音，保留其他乐器。

## 2026-11-01 播放器内音色映射

播放区的“音色映射”按钮打开当前曲目的原音色列表，播放中、暂停或停止时均可进入。选择某个原音色，再选自动、钢琴、马林巴、小提琴、中提琴、大提琴或低音提琴。目标尚未启用时，选取会自动启用，保留其他已勾选乐器；不要求用户先打开乐器菜单。列表只包含实际使用的旋律音色，按16行分页；“全部恢复自动”清空显式覆盖但不关闭已启用乐器。

修改映射保持当前歌曲时间与播放状态，并按新映射重建声音和表现。它属于公共播放配器，沿用播放权限和完整快照同步，切歌保留相同 Program 的设置；不修改源文件和曲库，也不写入个人硬件 MIDI 设置。界面号码为常见的001～128，数据仍用0～127；通道10固定走独立鼓组。取消一个已被显式映射的目标后，该音色显示未启用并静音，重新选取即可自动打开。回退音域、所有两两组合及同步编码见 [GM 音色分组与回退](19-gm-program-fallback.md)。

## 2026-11-01 主场景乐器复选框

乐器弹层各行改为独立复选框，选择后保持展开；可多选或全部取消。两种钢琴外观互斥并共享一个钢琴音色位，切外观不重新起音。收起入口显示单件名称、已选择数量或未选择乐器。勾选集合作为公共配器状态同步；回退只使用已选集合；提琴候选按音域中点分配，弦乐组已取消。多个模型同时展示，声音、琴键、弦光及粒子跟随各自实际路由。曲中更改集合保留音乐时间、播放/暂停状态；全部取消只关闭旋律，鼓组保持独立。


UI 只表达当前播放状态并发出本地命令，播放逻辑和 ownership 交给 Facade 与 Transport。数据和状态定义见 [统一约定](CONTRACTS.md)，远端应用规则见 [多人同步](04-multiplayer-sync.md)。

当前实际 Canvas 层级、弹层绘制与射线规则、生成器维护入口见 [15 UI 层级与绘制顺序](15-ui-hierarchy.md)。

## 1. 默认面板

默认面板包含曲名、播放状态、已播放/总时长、播放/暂停/停止按钮、可滚动曲库和预设收藏夹目录，以及本地音量和静音。进度条支持有权限的用户拖动定位；首版不提供倍速、搜索、随机、自动连播或粒子设置。

推荐布局为上方曲名和状态、中间进度条、下方控制按钮，曲目列表放在右侧或折叠区。键盘和瀑布流位于面板后方的独立表现区域；面板尺寸与模型缩放不参与 MIDI 逻辑。

```text
当前曲目                         [返回] 收藏夹
播放中                          全部曲目  12 首
03:12 / 05:48                   游戏音乐  2 首 / 1 个目录
━━━━━━━━━━━━                    古典音乐  4 首 / 0 个目录
[播放] [暂停] [停止]             …
音量 ━━━━━  [静音]               可滚动列表
```

当前皮肤参考 VizVid，采用深蓝灰圆角面板、近黑底槽和浅青色图标；左侧播放控制，右侧固定高度滚动曲库，溢出时显示滚动条。图标与圆角素材由本项目生成。状态同时保留文字，选中曲目以浅青竖线标记；拖动进度时预览目标时间，松手后提交定位，音量和静音继续只影响本地输出。

收藏夹目录由世界作者在编辑器预设。根目录显示“全部曲目”和顶层目录，点击目录进入其直属子目录和曲目；顶部显示当前位置，返回按钮回到上一级。“全部曲目”按完整曲库顺序显示所有曲目，目录内按该目录配置的曲目顺序显示。目录条目显示直属曲目与子目录数量，空目录保留并显示空内容提示。切换目录不会切歌或改动共享播放状态，远端切歌也不强迫本地用户切换目录。

## 2. 用户操作与结果

| 操作 | 前置条件 | 本地结果 | 公共结果 |
| --- | --- | --- | --- |
| 播放 | 有有效选曲、数据/音源就绪、CanControl | Stopped 从 0 开始；Paused 从冻结位置恢复 | 经提交入口发布 Playing 与时间锚点 |
| 暂停 | Playing、CanControl | 冻结曲目、音符、释放包络和瀑布流 | 发布 Paused 与固定进度 |
| 停止 | 已选曲、CanControl | 回到 0，取消声音预约、清空高亮和音符条 | 发布 Stopped/0，保留选曲 |
| 点击另一首曲目 | 曲目有效、CanControl | 清理旧曲，绑定新曲并保持 Stopped | 按稳定 songId 发布新曲和 Stopped/0 |
| 再次点击当前选曲 | CanControl | 幂等，不重启、不停音 | 无需发布同义快照 |
| 拖动进度条并松手 | 有效曲目和时长、CanControl | 拖动中预览时间；松手后重建目标位置，播放中继续播放，其余状态转为暂停 | 发布目标位置、状态与时间锚点 |
| 进入目录、返回或打开全部曲目 | 曲库菜单已生成 | 只更新本地路径与可见条目，可继续浏览当前播放之外的目录 | 不申请 ownership、不序列化、不切歌 |
| 修改音量/静音 | 本地音频已初始化 | 只改变本地输出增益 | 不申请 ownership、不序列化 |

Playing 时“播放”禁用，Paused 时“暂停”禁用；Stopped 时“暂停”禁用。无曲库或本地错误时禁用公共控制。短暂待提交期间允许新的用户操作替换待提交意图，不能积累多次 Play/Pause 命令队列。

所有操作入口再次检查许可和有效性，不能只依赖按钮的 interactable。UI 不自行调用 SetOwner，也不直接写 UdonSynced 字段。

## 3. 具体绑定

`MidiPlayerUI` 计划提供公开本地回调 `_OnPlayPressed()`、`_OnPausePressed()`、`_OnStopPressed()`、`_OnVolumeChanged()`、`_OnMuteChanged()`。编辑器将 Unity Button/Slider/Toggle 的回调接到同对象 UdonBehaviour 的 SendCustomEvent，再由这些回调调用 Facade。

曲目按钮使用 `MidiSongButton`：编辑器写入 `songId`、标题、Facade 和 UI 引用；`_OnClick()` 调用 `CommandSelectSong(songId)`。运行时不按列表显示下标同步曲目。重排曲库只改变显示顺序，songId 和网络查找保持一致。

目录源配置为 `MidiLibraryAsset.folders`，每项是可序列化的 `MidiLibraryFolder`，包含 `string path` 与 `MidiSongAsset[] songs`。路径用 `/` 分级，例如 `游戏音乐/Arcaea`；未显式配置的父目录自动补齐。同一首曲目允许出现在多个目录，同一目录内不允许重复，所有目录曲目必须已包含在完整曲库 `MidiLibraryAsset.songs` 中。目录按配置中各路径及父路径首次出现的顺序显示；在 Inspector 拖动调整分支顺序时，应把父目录与该分支全部子目录一并调整，仅移动显式父目录不会覆盖较早子目录的排序。目录内曲目按该项 `songs` 顺序显示，仍通过稳定 songId 选曲。

作者选中曲库资产后，可在 Inspector 编辑目录路径、曲目归属与顺序，使用“检查目录”查看配置错误，再用“保存并同步场景目录”更新当前已加载场景中使用该曲库的播放器菜单；同步后需保存对应场景。`Tools/Music MIDI Player/Update Player UI` 更新主 Prefab 的菜单。玩家只能浏览和选曲，不在世界内新增、改名、删除目录或保存个人收藏。

基础调用契约如下：

| 本地接口 | 参数/行为 |
| --- | --- |
| `MidiPlayerFacade.CommandPlay()` | 幂等检查、恢复或起播、本地推测和提交 |
| `CommandPause()` / `CommandStop()` | 由 Facade 统一读取时钟和执行清理 |
| `CommandSelectSong(string songId)` | 校验稳定 ID，绑定新曲并停止 |
| `CommandSeek(float progress)` | 校验权限并将进度限制在 0～1，重建目标位置并提交共享时间锚点 |
| `MidiControlGate.CanControl()` | 返回本地许可与 Ready 条件，不等于 IsMaster 或 IsOwner |
| `MidiPlayerUI.RefreshState()` | 读取 Facade 状态；不产生任何网络提交 |
| `PianoVoicePool.SetLocalOutput(float volume,bool mute)` | UI 缓存音量与静音后成对传入；音量 clamp 到 0～1，取消静音还原原值 |

这些调用属于同一客户端内的 UdonSharp 方法。UI 和 Facade 使用无同步对象，不对外提供跨网络命令 RPC。

## 4. 状态与错误文案

| 条件 | 玩家文字 | 行为 |
| --- | --- | --- |
| 无曲目 | “暂无可播放曲目” | 禁用公共控制，保留音量 |
| 就绪且停止 | “已停止” | 已播放 00:00，键盘常态，瀑布流清空 |
| 正在播放 | “播放中” | 时长与进度更新 |
| 暂停 | “已暂停” | 保持冻结时间和视觉状态 |
| 短暂重建 | “准备播放…” | 暂时静音，完成后进入目标状态 |
| 操作提交未完成 | 可选轻量“同步中…” | 不阻塞音量和静音；不弹确认框 |
| 操作未能保留 | “播放状态已更新” | 收敛到有效远端快照，不把丢失操作假装成功 |
| 曲库或音源不一致 | “播放器配置不一致，请联系世界作者” | 本地静音并停止应用无效数据 |
| 缺资源/损坏配置 | “播放器暂不可用” | 在开发日志记录具体诊断 |
| 控制许可关闭 | “播放控制已锁定” | 禁用公共操作，本地音量和静音继续可用 |

正常网络更新不反复显示准备状态；只有需要切曲、实际重建或恢复资源时才使用它。Owner 名称、网络序号、池容量、数据哈希、SDK 限制和堆栈不放进默认玩家面板。

## 5. 时间和曲目显示

总时长使用 `playbackEndMs = durationMs + maxReleaseMs`，包含末尾释放安全尾垫。已播放时间来自本帧 Clock 快照，显示可按 0.1～0.25 秒刷新；无需每帧格式化字符串。长于一小时的文件使用 hh:mm:ss，否则使用 mm:ss。

曲名来自曲库资产的显示标题，默认可用文件名去扩展名并允许作者编辑。完整标题保留在数据中，显示端使用可换行或省略号，不通过截断字符串改变 songId。曲目列表显示选中状态；条目标题重复不影响查找。

停止后不自动播放下一首。自然结束保留释放尾音，再由当前 Owner 发布 Stopped/0；终态显示回到“已停止”。收藏夹目录仅用于手动选曲；未来的自动连播应由单一公共推进者处理。

## 6. 本地许可

`MidiControlGate` 默认开放。作者可在 Inspector 配置初始锁定，或由自己的本地权限系统调用明确的许可方法。首版不自带身份服务，不把实例 Master 当成唯一可操作玩家。

许可关闭只影响本地用户发出公共操作。接收他人状态、正常本地播放、曲终自然收敛和符合维护条件的失活接管仍按同步方案执行；维护接管不能据此改变曲目或播放意图。

## 7. Prefab 交互与可用性

面板使用 World Space Canvas、EventSystem/VRChat 世界所需的交互组件和已导入的 TextMeshPro 字体资源；所有引用由配置工具接线。按钮应在桌面与 VR 指针操作下可点击，文本在目标世界尺度下可读，避免透明覆盖层截获射线。

音量和静音设置仅保留当前本地会话，不在 P0 加入跨会话存档。默认静音为 false；默认音量以音源削峰验收结果确定。音量变为 0 不停止曲目，恢复音量后继续听到当前进度。

## 8. 验收

验证播放、暂停、停止、切曲及同义操作的按钮状态；验证锁定后所有公共操作入口均被拦截；验证选择重复标题仍命中正确 songId；验证音量/静音不会取得 ownership；验证重建与网络收敛后 UI 不保留旧曲名、旧进度或旧按钮可操作性。

目录验收应覆盖根目录与“全部曲目”、多级路径和返回、自动补齐父目录、空目录提示、目录与曲目顺序、同曲多目录选中态，以及滚动浏览。验证目录配置拒绝重复曲目和完整曲库之外的曲目，场景同步及主 Prefab 更新保留目录配置。验证锁定时仍可浏览目录，目录导航不申请 ownership、不提交网络状态、不打断播放。

具体多人与性能场景见 [验收计划](09-performance-and-validation.md)，生成接线见 [编辑器与 Prefab](08-editor-and-prefab.md)。

## VR / PC 实时演奏（2026-10-27）

`MidiPerformanceInput` 将 VR 手指触键和 PC 按键送入 `MidiPlayerFacade.PerformNoteOn / PerformNoteOff / PerformControlChange`；硬件 MIDI 回调也转发至这三个入口。音源、力度、琴键、瀑布流、特效、实时演奏同步、晚加入恢复和个人练习判定继续沿用 MIDI 链路。公共播放器须处于停止状态；个人练习场景沿用练习状态规则。

- 设置面板可独立勾选左右手各五根手指，默认只开启左右食指；这是本地设置，不影响其他玩家。使用 Avatar 的末节指骨估算指尖，缺少指骨时跳过对应手指。仅从上方下压触键，带松键容差；多根手指按同一键时，最后一根离开才松键。
- PC 必须坐在该乐器前的演奏椅上。默认从 C4 开始，`A W S E D F T G Y H U J K O L P ; '` 依次对应 18 个半音（C4～F5）；支持同时按多个键。`Z / X` 降低／升高一个八度，`Space` 为延音，`Enter` 离座。换八度时已按住的键保持原音高，按原键松开。
- 离座、停用输入、关闭对应手指、切换乐器、重生、换 Avatar、播放器状态变化时释放本输入持有的音符。PC 椅子禁用移动／跳跃的默认离座，避免 WASD 和空格与演奏冲突；Enter 和再次交互可离座，VR 保留通常离座方式。
- 有乐器路由器的主场景中，虚拟输入为七个乐器目标分配独立通道，从 `midiChannel` 向下循环并跳过鼓组通道索引 9。默认钢琴、马林巴、小提琴、中提琴、大提琴、低音提琴、弦乐组分别使用索引 15、14、13、12、11、10、8，力度 100；两个钢琴外观共用通道。硬件 MIDI 应避开正在使用的虚拟乐器通道，避免同通道同音高共享 MIDI 身份。没有路由器的练习／分发实例仍使用原单一 `midiChannel`。
- 触键区域按实际模型静止网格烘焙，钢琴为 88 键，马林巴只生成实际存在的 61 个琴条，不在空白处生成虚拟琴键。`MidiPerformanceBuilder.Configure` 负责接线；`UpgradeAll` 更新两个播放器预制体及主场景、Demo、Practice 场景。

真实 VR 指骨、不同 Avatar 的触碰手感、PC 键盘硬件多键冲突和双客户端网络效果仍需在 VRChat 内体验确认。

### 多选时的手动音色（2026-11-01）

- VR 逐台检测当前启用的实体键盘／琴条，指尖历史保存世界坐标，再变换到各台乐器的局部区域。左右手可以分别弹钢琴和马林巴；同音高跨乐器分别计数和松键，多指同键仍只起一个音。弦乐延续现有无键盘触碰几何的设计。
- PC 的起音目标来自当前演奏椅的 `instrumentIndex`，覆盖钢琴、马林巴及五类弦乐。多选不会因座位与全局 `selectedInstrument` 不同而离座；取消勾选或隐藏当前座位、主动离座及状态变化沿用释放入口。已按下的键保留原音高、乐器及通道，延音也在原通道释放。
- 手动起音携带明确目标，只能播放已启用乐器，不经过 GM 回退；曲目和未映射的硬件 MIDI 继续沿用原 Program 路由。弦乐使用对应目标的独立奏法，自动模式保留既有默认。实时事件和稀疏恢复快照保留该目标，取消勾选后不会把原手动音符重映射到其他乐器。

### 硬件 MIDI 通道映射（2026-11-01）

官方 `VRCMidiListener` 的 NoteOn 进入现有 Facade，根据 `hardwareMidiChannelTargets[16]` 选择已启用目标，随后复用手动演奏的起音事件及恢复快照。没有新增设备驱动、监听器或独立输入层；PC／VR 输入不经过这张硬件映射表。

数组索引 0～15 对应 MIDI 通道 1～16；值 -1 为自动路由，0～6 分别为钢琴、马林巴、小提琴、中提琴、大提琴、低音提琴、弦乐组。所有旋律通道默认自动，玩家无需打开设置、识别通道或选择映射即可输入 MIDI：单选时落到当前启用乐器，多选时沿用既有 Program 回退顺序；空集旋律静音。通道10始终为独立鼓组，其映射值忽略。已保存记录和玩家主动设置的映射原样保留，不因默认值更新而重置；显式目标未启用仍静音，可在高级页改回自动。没有路由器的旧单乐器／练习实例保留原输入行为。

作者也可在 Facade Inspector 的 `Hardware MIDI Channel Targets` 中修改，或调用本地 `SetHardwareMidiChannelTarget(int channel, int target)`；该配置不申请 ownership、不修改公共勾选集合、不写入公共播放快照。每次起音同步已经选定的目标，各端不使用自己的映射表重新解释他人的输入。修改映射只影响后续起音；按住音、踏板持续音及晚加入恢复保留原目标，NoteOff、零力度 NoteOn、CC64／11／120／121／123 继续使用原通道。硬件与 PC／VR 同时演奏时仍须避免使用相同通道、相同音高的身份。

游戏内默认从 **设置 → MIDI 演奏** 进入，提示“在你的键盘上按一个键”。官方硬件 MIDI 的首个有效旋律 NoteOn 自动识别输入，随后只显示已启用的乐器；选择后显示“已设为某乐器，可以开始演奏”，后续按键立即使用新音色。识别阶段的按键不触发原映射，PC／VR 输入不参与识别。鼓组输入提示改用旋律键盘，第10通道仍固定鼓组。可随时重新识别；没有已启用乐器时提示先启用乐器；已记住但未启用的乐器不自动打开公共勾选集合，而是要求重新选择。曲目尚在播放或演奏权限关闭时只显示已设置，并提示等待／停止曲目，不自动取得控制或停止共享播放。

需要分区／多通道编曲时打开 **高级：通道映射**，使用原16行映射页。“自动”及未启用目标的显示规则保持原样，Back 返回 MIDI 演奏页；关闭设置统一关闭所有 MIDI 子页。钢琴两个外观共用“钢琴”目标；修改仅影响后续起音，不切歌或重建旧音。所有新增文字支持英文、简／繁中文与日文。

### MIDI 常用选择的持久化（2026-11-01）

已核对当前 SDK 3.10.5 与[官方 PlayerData](https://creators.vrchat.com/worlds/udon/persistence/player-data/) 支持：Facade 使用 `OnPlayerRestored`、`TryGetString` 和 `SetString`，无需新增 PlayerObject 或设备接入层。保存16项映射及最近通过普通流程选定的输入；下次进入同一世界可直接使用该选择。官方输入不暴露设备身份，因此不会按硬件名称分别保存，换键盘后可重新识别。

键默认 `MusicMidiPlayer.MidiPreferences.v1`，可通过 Facade 的 `midiPreferencesKey` 为同世界内不同播放器指定稳定且不同的键，空键停用保存。记录为18字符的版本化数据，加载时完整校验后再应用；不保存公共乐器集合或当前音符。仅处理本地玩家的恢复事件，读写等待 `OnPlayerRestored`，恢复前新修改的通道与当前选择优先保留，避免迟到记录覆盖刚做的设置。选择变化合并延迟0.5秒写入，相同内容不重复写，不逐音符存储。

PlayerData 由 VRChat 自动同步和持久化，配置不进入本播放器的公共 Transport 快照；未恢复或不可用时仍可在当前会话使用设置。上传世界按玩家账号保存，Build & Test／ClientSim 的存储环境不同；Editor 验证不能代替真实客户端离开世界后重进的保存验收。

### 按设备显示输入设置（2026-10-27）

VR 输入区使用左右手示意图，十个手指开关分别位于对应指尖；“一键全选”和“全部取消”同时更新全部手指。取消已按下的手指会沿现有音符引用计数释放输入。PC 仅显示键盘布局、坐下演奏说明与快捷键；VR 仅显示手指设置及摇杆灵敏度。依据本地玩家 `IsUserInVR()` 选择界面，与 MIDI 设备连接状态无关，也不改变其他玩家的设置。
