## 工作方式与既有内容保护

- 文档与 AI 工作从[当前源码地图](../Developer/CURRENT_STATE.md)和[工作指南](../Developer/AI_GUIDE.md)进入；文档状态见 `Docs/doc-map.json`。新乐器准入由[贡献政策](../Contributing/README.md)、[机器政策](../Contributing/instrument-policy.json)及[预算口径](../Contributing/BUDGETS.md)统一规定；不把历史草案当作另一份已批准规则，也不为迎合既有资产而擅自放宽新贡献上限。

- 只改本次需求和必要依赖，不顺手重构、清理、迁移或扩展流程。交付代码、资源、引用、接线及必要本地化；不要仅修改生成器而遗漏实际对象。
- 按 `vrchat-world-dev-habits` 技能执行项目开发习惯。先确认当前工程、场景、播放状态及既有改动；保留其他会话正在进行的工作，不覆盖或回滚陌生修改。
- 保留资源 GUID、`.meta`、稳定曲目 ID、场景引用、Prefab 覆盖和对象身份。优先增量更新，避免全量重建及无关重存。
- 恢复前先查历史会话和备份，按最新有效要求恢复；不把废弃方案或旧快照当成现行规格。AGENTS.md 只保留核心约束和文档索引，详细约定写入 docs；更新时保留仍然有效的要求。
- Unity 编辑、状态读取和截图优先使用 Unity MCP。遵守当前任务明确的操作方式；若任务禁用操控电脑，不用桌面自动化绕过。
- 所有浏览器操作显式指定 Google Chrome / `chrome`，不得使用、唤起或回退到 Edge。命令打开网页及本地 HTML/PDF/SVG 时使用 `C:\Program Files\Google\Chrome\Application\chrome.exe` 并正确传参。发现授权范围内的 Edge 调用应改为 Chrome；Chrome 不可用时说明原因。

## 逻辑与同步

- 数据、播放逻辑、声音与表现分离。UI 通过 Facade 发本地命令，时钟推进音乐时间，Sequencer 处理音符生命周期；动画、粒子和音频不得反向改变权威播放状态。
- 播放器 Owner 与实例 Master 分开。公共播放快照由可转移 Owner 发布，其他端本地跟随，不把普通输入全部改为 Master 中央处理。
- 网络 Transport 独立对象、Manual Sync；本地组件使用 None。运行数据、UI、时钟和声音池不能跨实例串线。
- 播放、暂停、停止、切歌、定位、实时 MIDI、VR 手指和 PC 键盘输入应复用现有音符处理链，修改时检查恢复、释放、踏板、代次及过期任务，避免重复起音或旧状态污染。
- 2026-11-01 已取消播放推进 100 ms、256 事件预算、同步误差 100 ms 自动重建及 80 ms 起音限制；正常推进完整消费到期事件，首次处理的迟到音符仍保留起音并顺延本声部释放/结束。不要恢复这些跳音门控。普通同曲 Playing 快照只更新目标，主动 Seek 使用明确标记；定位/晚加入/暂停恢复保留真实年龄语义。64 声部与鼓组容量另按既有规则维护。
- 主场景钢琴外观与乐器选择共用菜单、曲库、输入、Transport 和声音池；两个钢琴外观共用音源，切换外观不重新起音。新增乐器沿用这一体系。
- 新乐器的类型登记、现有实现基线及同次代码 / 文档更新位置见 [新乐器追加规范（待审阅草案）](18-adding-instruments.md)；主场景已接入的 Program 分组、例外与复选集合回退见 [GM 音色分组与回退](19-gm-program-fallback.md)。仅已勾选乐器可作为回退目标；空集旋律静音，鼓组独立。独立练习和分发 Prefab 沿用其既有配置。

## 曲库与歌曲导入

- 新增歌曲同时更新目标场景曲库、目录及菜单接线；保留稳定 `songId`、源 GUID 和重导入映射，不用文件名替代唯一身份。
- 按源 MIDI 内容哈希去重。用户指定同曲的新版本时更新既有曲目，保留引用，不单纯因内容哈希变化就当成另一首。
- 清理导入文件名、填写曲名与作者。作者未知时先核实，仍无法确认则留空，不编造；用户明确指定的署名和分类优先。uaaaak 改编作品位于独立子目录 `游戏音乐/uaaaak`（2026-11-02 用户确认），不自动混回 arcaea。
- 分类支持子目录、进入和返回，不要求同时展开多个分支。搜索覆盖整个曲库；目录浏览和搜索只影响本地 UI，不切歌、不申请 ownership。
- 保留完整 MIDI 0～127 音高。实体音域外按黑白键排列延伸并使用采样变调，不丢弃、不折叠八度；实体键/琴条以外不驱动不存在的模型。

## 音源与声音

- 已确认的钢琴规格：Salamander 每 3 半音、4 个真实力度层 v3/v7/v11/v15；马林巴：Iowa Yarn 的全部 60 个实录根音、单力度层。两者源文件为 48 kHz 立体声 Vorbis q4，沿用现有许可及署名。不得从旧方案恢复单层 v9 钢琴或稀疏 VCSL 马林巴。
- 四层钢琴用力度选层，保留录音的响度差异，不额外叠加旧力度幂衰减、不逐层归一化。马林巴与其他 bank 沿用各自有效规则；不要全局套用钢琴特例。
- 音色修改沿用现有 bank 与烘焙工具，更新映射、峰值、哈希和运行数据；不只更换 Inspector 引用。保持实时输入、播放、暂停、定位和跨音源持续音的一致性。
- 默认世界内 3D 声音，保留本地 2D 选项。2D 声音的响度和声像不得随玩家位置或朝向变化：切换时同时关闭 AudioSource 空间化并绕过 Reverb Zone，切回 3D 恢复各源原有设置；共用声音池中的所有乐器与鼓组一致。音量和静音仅影响本地；2026-11-02 起“音量平衡”默认开启，可本地关闭；采用 20 ms 采样能量包络压缩，开关保留既有序列化字段和回调。不要改写已调好的本地音量、音源区域增益和空间参数；算法及默认压缩参数见第 13 册。
- PC 与移动端统一 64 声部的最新定案；不要恢复 256 管理/64 发声的旧方案或未经用户确定的移动端 24 限制。区分声音池容量、真实/虚拟声道与预约占用，不能靠增加队列掩盖实际声道限制。
- 上述 64 指现有共用物理 AudioSource 预算。当前弦乐每逻辑音使用一对源，鼓组代码可预留末尾 16 源；弦乐最多 32 音，有鼓组预留时最多 24 音。这是源码容量，不是恢复旧移动端限制或已通过实机性能验收；当前接线状态见第 18 册。
- SDK 重载可能回写 AudioManager，沿用项目现有修复与显式项目开关；分发导入其他世界时不自动修改其全局音频设置。
- 响度、压缩源体积、解码内存、构建下载体积分别报告，不能互相替代。声音过小时先检查原始采样、力度映射和实际 AudioSource 输出链，不凭猜测改采样或增益。

## 瀑布、琴键与表现

- 新乐器的表现按自身演奏方式设计，不强求钢琴窗、音符瀑布或落琴音符。2026-11-01 用户已取消旧的强制钢琴窗要求；优先用发声部件高亮、轻量粒子及适合的演奏动作表达状态。弦乐已要求移除该窗并固定琴体，保留运弓，以对应琴弦亮起和近处粒子作为反馈。详细约定见 [新乐器追加规范第 2.1 节](18-adding-instruments.md)，不因本条批量改造已有钢琴或鼓组。
- 一首歌一个由 MIDI 哈希决定的主色调，黑键/白键使用同色系的深浅配色；音符、琴键高亮及粒子跟随该调色板，不恢复每个音符独立乱色的旧方案。
- 音符保持实心水晶/宝石质感，长度变化不得拉伸上下端部。短音放大由现有 Shader 处理并限制幅度，保持时值长度、音高位置和落点，不恢复逐帧两两重叠比较或无限空间错层。
- 表现优先轻量 Shader/Emission；呼吸发光不新增逐音符 Update 或大量实时光源。保留现有两类粒子及实时输入的对应效果。
- “键盘后沿”指整排已绑定琴键/琴条的最后沿，不是单键铰链、琴壳或整台琴的包围盒；马林巴双排琴条和域外落点需一致适配。
- 播放前保留约 3 秒曲名/作者开场，作者可为空；跟随当前乐器，开屏位置约在键盘上方 50 cm。音符从高处进入，不直接在落点附近刷新。
- 所有琴的实体 `HitLine` 模型已要求移除，不因重建表现而重新生成。

## UI、输入与本地化

- UI 沿用 VizVid 风格与现有配色、圆角、图标、字号和间距；新设置与既有面板一致，不放实现说明或开发限制。
- 修改 UI 前阅读 [UI 层级与绘制顺序](15-ui-hierarchy.md)，层级、路径或接线变化同步更新该文档。
- 背景在普通控件前；所有普通控件（含搜索框）在三个弹层前；弹层互斥。`Backplate` 使用正面剔除材质，必须最后绘制且不接收射线，不可按名称把它移到最前。生成/增量更新后统一调用 `ConfigureHierarchy()`。
- 保持已有 `transform.Find` 路径与回调，不为排序擅自增加中间容器。操作面板碰撞器为 trigger，不形成物理阻挡。
- 曲库滚动只响应相应指针/右手输入，不让左手摇杆或 PC 的 WASD 移动意外驱动菜单。摇杆灵敏度为等间距标记的 0.5/1/2/4/8/16 倍档位；音量保留连续调节。
- 进度条支持拖动预览、松手后提交；小节吸附为可选项。避免拖动每次值变化重载整曲，不恢复已删除的“每帧最多解码条目”设置和 UI。
- 世界内与 Editor UI 沿用现有 I18N/字体 fallback。语言入口仅英文、中文、日文三个；中文简繁跟随客户端，不增加单独繁体入口、台湾旗帜或“自动”入口。
- VR 在设置中选择左右手启用手指，按钮沿指尖布局并保留全选/取消；PC 坐上乐器前的椅子后才可键盘演奏。PC/VR 分别显示对应设置，输入仍与 MIDI 共用逻辑。

## 验证与交付

- `MidiBuildValidator` 的完整播放器检查仅用于显式配置、维护、导出或手动诊断，不作为 VRCSDK 日常构建的自动硬门槛；构建回调中的项目音频同步失败只警告并继续（2026-11-02）。不要恢复由 UI 摘要、表现配置等检查中止整个世界构建的门控。
- 按当前任务要求和改动边界验证，不自行增加构建、打包、发布或长时间验收。用户说“不要构建”“不用测了”时遵守其对应任务范围；旧会话中的一次性授权不永久沿用。
- UI 目视问题优先通过 MCP 实际渲染/截图核对。静态检查、Editor 代理、backing Udon、ClientSim、真实 VRChat 和双客户端验证分开描述，不把一种结果当作另一种已通过。
- 检查 Console 的时间、来源及新增数量；临时对比脚本的旧警告不能直接归因正式播放器。临时检查对象和状态结束后恢复，测试资料与分发资源分开。
- 简要说明实际改动、检查结果、未验收项与现有阻塞；并行工作引入的错误先定位，不擅自撤销其他人的改动来获得通过结果。
