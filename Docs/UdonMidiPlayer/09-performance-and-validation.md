# 性能预算与验收计划

本文件定义实施后要收集的证据和通过条件。数值为 PC 首版的初始目标，当前尚无运行测量；参数共同来源见 [统一约定](CONTRACTS.md)。Quest 专项优化留在 P1。

## 2026-11-02 Windows 性能优化实施（未运行验收）

本轮依据静态调用链和主场景配置逐项实施，未运行测试、Play Mode、Profiler、构建或真实客户端验收；下述是源码行为变化，不是实测帧率／耗时收益。后续章节的旧预算和测试矩阵保留为历史设计，现行播放规则以第 17 册及源码为准。

- **表现刷新入口**：有 `MidiInstrumentRouter` 时由路由路径刷新启用的乐器，单乐器路径只用于无 Router 的配置；同一帧内的重建不再紧接着重复刷新。正常帧的路由按键计数在 Sequencer 推进后计算一次。音频仍先回收过期声部，再处理到期起音。
- **UI 状态更新**：歌曲按钮不再逐帧遍历。首次刷新／权限变化更新全表；选曲变化只更新旧、新选中行（查找新行仅在选曲变化时进行）。乐器选项、奏法、按钮状态和对应布局按权限、加载、播放、语言及选择变化更新，进度条保持连续更新，时间文案沿用 0.2 秒节流。UI 层级和回调不变。
- **合奏音频结算**：播放帧将到期事件、恢复和前视预约放进可嵌套的输出批次，批次结束统一查取预烘焙能量包络、计算音量平衡系数并写回全池音量；PC／VR 输入及远端实时 MIDI 事件批次同样收口。新增声部立即写自身音量，单次硬件 MIDI 回调仍即时结算。抢占比较使用当前包络；同曲同帧同毫秒同通道的 Expression 查询复用。维持共用 64 个物理源、鼓组分区、弦乐双源、完整消费到期事件及迟到音符保留起音的规则。
- **瀑布 Shader 动画**：`WaterfallVolume` 支持实例属性 `_Color`、`_NoteTiming`（起音／松键秒数及文件／实时模式）、`_NoteOrder`。每个瀑布持有一份私有共用材质和自己的 `_VisualTime`，不使用全局 Shader 时间替代播放时钟。入槽／实时松键／重建时上传属性，稳定帧只推进共用时间；位置、长度、窗口上下端收缩、命中亮度由顶点／片元阶段计算。Udon 保留可见池、候选选择、回收、音符逻辑和粒子事件，不提交整首曲目的不可见网格。
- **材质与剔除**：GPU 动画路径不再为瀑布创建 88 组普通／命中材质，沿用既有水晶网格、端部修形和短音有界放大。每个槽位的 Transform 在入槽时覆盖整段可见高度，顶点在其中移动，因此垂直剔除范围不依赖 Shader 位移回写；暂停不推进时间，Seek／晚加入重建当前窗口，实时演奏使用本地实时时钟。自定义非 `WaterfallVolume` 材质仍走既有 CPU 几何路径。GPU Instancing 的实际合批结果未测量。
- **加载收尾分帧**：解码、Program 路由、鼓组发声索引、鼓组轨道索引和各乐器绑定共享现有 `decodeFrameBudgetMs`。鼓组按有限记录数执行 `BindStep`，各 View 逐个绑定；不再同时绑定选中 View 和路由数组内的同一 View。瀑布 slot+1 编码与声音池正代次标记利用数组默认零值，取消按整曲音符数写入 -1 的 Udon 初始化循环。切歌重置加载游标；完成后用最新 Transport anchor 恢复。预算在步骤间检查，单个数组分配、Unity 原生调用或固定规模组件初始化仍可能超过预算，并非严格单帧上限。

本轮未迁移 MIDI 解码、声音调度、权威状态、踏板、网络和声部选择到 Shader；未扩展到有限数量的琴键／鼓件／运弓动作或粒子重写。主场景、曲库、分发 Prefab、GUID、`.meta` 及音源参数未重存或更换，现有引用直接使用更新后的脚本和 Shader。

## 1. 预算与测量口径

| 项目 | 初始设计值/目标 | 验证方式 |
| --- | --- | --- |
| 声音池 | 默认 64，可配置 | 同时统计预约、发声、释放、自然结束和回收数量 |
| 可见音符条池 | 默认 512，前视 3 s | 确认可见数及溢出次数，超限只降级表现 |
| 本地校准 | 0.5 s 检查一次 | 记录检查、轻量相位修正、强制重建次数 |
| 心跳 | Playing 时约 3 s，无新快照才补发 | 记录实际序列化次数、心跳数和字节数 |
| 逻辑时间偏差 | 正常稳定网络中目标 ≤100 ms | 两端以共同服务器时间对齐采样，报告 P50/P95/最大值 |
| 实际音频起音差 | 单独实测，初始目标 ≤100 ms | 统一时间基准采集两端同一音符的起音；逻辑日志不能替代音频证据 |
| 典型曲目本地 CPU | 初始目标约 2 ms/帧以内的播放器增量 | 同场景、同设备、有/无播放器的 Profiler 对照；M0 后校准预算 |
| 稳态分配 | 播放核心、声音和表现更新不持续分配托管内存 | 检查分配样本及 GC；UI 字符串只在低频刷新时更新 |
| 音源解码内存 | 初始目标 ≤64 MiB | 按 Unity 实际加载格式测量，不能只看压缩文件大小 |
| 曲库数据体积 | 分别报告源资产、烘焙裸数组和运行驻留量 | 曲库与运行缓冲区分开统计，不用磁盘体积代替运行内存 |

CPU 目标不是未知设备上的保证。验收记录必须包含 CPU/GPU、VR/桌面、刷新率、场景负载、音频配置、曲库规模和客户端版本。若现有世界已接近预算，先降低表现和音源资源预算，不改变公共播放结果。

64 个 AudioSource 不代表一定有 64 个实际可闻声音。Unity/VRChat 的全局 real voices、其他世界声音、虚拟化和优先级一起决定输出；M0 和密集曲目验收必须实际听到/采集对应复音，不能仅检查 isPlaying。

## 2. 内容规模样本

建立三类自制或可分发测试曲：短功能曲、约 50,000 音符的典型大曲、约 100,000 音符或高峰并发的压力曲。压力曲可由工具生成，数据规模和音符密度独立可控。

每首曲目记录：音符数、事件数、时长、峰值按键并发、踏板后并发、最大 3 秒可见音符数、检查点 CSR 总元素数、裸数组体积。检查点内存随持续音与曲长增加，不能只按音符数线性估计。

对超出设计预算的内容，Editor 输出警告并展示可调整的轨道、声音池和视觉池；不静默删掉有效逻辑音符。格式损坏、索引不合法或 int 毫秒溢出必须报错，不能截断成一首“看似导入成功”的曲目。

## 3. 固定功能测试集

| 编号 | 内容 | 应有结果 |
| --- | --- | --- |
| D01 | Type 0/1、多个轨道、缺省 tempo 与多次变速 | 转换后时间正确，轨道合并稳定 |
| D02 | velocity=0 的 NoteOn、同音快速重复、同通道同音重叠 | 正确配对；前一个音符结束不误停后一个 |
| D03 | 同音跨通道、CC64 按下/松开、踏板中重击 | 通道独立，键盘松开与声音延续各自正确 |
| D04 | 同 tick/同毫秒事件、零时长音符 | 顺序稳定，不留下负计数、挂音或闪烁高亮 |
| D05 | 孤立 NoteOff、未配对 NoteOn、尾部踏板未松 | 诊断/修复策略可重复，曲终可收敛 |
| D06 | 音域外音符、打击乐、未支持表达 | 按配置跳过/诊断，统计数量准确 |
| D07 | 损坏头/轨道、Type 2、SMPTE、过长时间 | 明确失败，保留上一份有效生成资产 |
| L01 | 反复 Play/Pause/Stop、同义按钮、快速切曲 | 状态机幂等，无旧曲声音、残留高亮或过期 DSP 预约 |
| L02 | 暂停位于长音、踏板和释放尾音中 | 曲目及包络冻结，恢复采样位置正确、不重打起音 |
| L03 | 自然曲终与主动 Stop | 自然曲终保留安全尾垫；主动 Stop 清理并回到 0 |
| L04 | 人为帧卡顿、暂停窗口附近卡顿 | 直接重建当前状态，不把历史音符集中补播 |
| A01 | 大和弦、64 及以上声部、长音自然衰减完 | 池回收可预测，已结束采样不重新起音，无持续削波 |
| V01 | A0/C8、全部黑白键、超长音符、密集可见窗口 | 横坐标、宽度、长度、命中与裁剪正确 |
| V02 | 停止后选曲、暂停和强制重建 | 停止时清空音符条；冻结和恢复一致 |

音频、数据、逻辑和视觉各有独立判据。声音被预算回收不应改变音符逻辑；视觉条不足不应少播音符。

## 4. 多人测试矩阵

至少两个实际客户端；需要失活、交接和并发时增加第三个客户端。ClientSim 可用于本地交互辅助，不代替真实客户端同步证据。

| 场景 | 验收条件 |
| --- | --- |
| A 播放、B 暂停/停止/切曲 | B 在有权限时本地响应并提交；最终各端收敛到当前 Owner 完整快照 |
| A/B 同时操作 | 不声称两次操作必保留；最终 Owner 状态一致，输掉的推测操作撤销，无永久分叉 |
| ownership 申请未成功/序列化失败 | 不无限抢权或循环发送；取消/重试边界符合同步分册 |
| 播放中、暂停中、释放尾垫中加入 | 应用最新快照，音符/踏板/冻结进度正确 |
| 数据初始化慢于首个快照 | 缓存最新快照；就绪时追当前进度，不从收到快照那一刻的旧进度开始 |
| Owner 正常离开 | 新 Owner 延续当前播放，不自动回到 0；适时发布当前状态 |
| Owner 仍在实例但客户端不活跃 | Playing 维护在随机退避后接管，接管者不擅自改曲或暂停 |
| Paused/Stopped 长时间无人操作 | 不因缺心跳主动抢权；之后有权限的用户仍可接管控制 |
| 旧心跳、非 Owner 心跳、补发请求密集 | 无效心跳不延长健康期限，补发有节流 |
| 收到远端状态 | 没有 Command/SetOwner/再次提交的回环 |
| 曲终同时到达 | 只有当前 Owner 发布公共终态，旧曲终不能覆盖新曲 |
| 曲库或音源 hash 不同 | 本地明确错误并静音，不猜曲、不覆盖正常公共状态 |
| 同场景两个播放器 | Owner、曲目、音符、UI 与本地音量互不串线 |

记录公共命令传播延迟和稳态时间偏差为两个指标。首次开始时远端加载/序列化迟到，可以定位到当前采样位置，但不能把错过的瞬时起音“恢复为已经同步听到”；应保留这一实际边界。

## 5. 诊断数据

开发态记录每个实例的实际 Owner、待提交意图、快照作者/序号、曲目 ID、Clock 目标/本地进度/偏差、applyGeneration、事件游标、有效声部和可见条数量。音量、许可等个人状态不汇总到某个玩家端。

网络层记录 OnPostSerialization 的成功与字节数，以及 takeover/rollback/snapshot request 的原因。日志只在变化或异常时输出，避免逐帧或逐音打印。默认玩家面板只显示 [UI 分册](07-controls-and-ui.md) 中的必要文案。

## 6. 接入与重导入验收

验证一份全新场景中“拖入 Prefab → 配置曲库 → 应用配置 → 播放”完整闭环；对比源文件移动、生成资产重导入、曲库重排后的 songId 与场景引用。使用两个独立实例检查交叉引用检测。

分发验收使用独立的干净世界工程实际导入成品；核对所有自有 C# 类型位于 `MusicMidiPlayer.*`、两个程序集名称及 U# Runtime 注册正确，Editor 和解析依赖不进入运行引用。加入同短类名但不同命名空间的测试组件，验证共存；检查菜单/Shader 前缀和升级后脚本、程序资产、Prefab GUID 引用。具体命名表见 [分发约定](12-namespaces-and-distribution.md)。

构建检查要能识别未烘焙、过期 hash、损坏数组、缺字体/材质/采样和 Udon 编译失败。失败不能显示“配置完成”或输出一份使用旧数据的新构建。

## 7. 验收记录模板

每次正式验证至少记录：日期/客户端版本、工程与内容版本、场景/设备/音频设置、测试曲及统计量、参与客户端角色、操作步骤、预期/实际、数据/音频证据、是否通过及未解决问题。

本次文档阶段仅做文件完整性与设计一致性检查。后续实施的编译、播放、Profiler、双客户端和发布验收均应实际执行后再标为通过。
