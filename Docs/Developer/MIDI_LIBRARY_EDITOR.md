# MIDI 曲库编辑器：操作与界面契约

本次目标：在黄金角通道配色版本上交付统一的 Unity 曲库编辑器。交互参照 [VizVid 的播放列表编辑器](https://code.moka-rin.moe/VVMW/docs/index.html#editing-playlists)，独立实现，不复制其代码或引入视频后端。

## 用户看到什么

打开 **Tools → Music MIDI Player → Import MIDI** 或播放器 / 曲库上的编辑入口。顶部显示正在编辑的曲库和目标，提供“重新载入”“保存并应用”和“更多”。左侧为分类，可新增、重命名、拖动排序、删除；右侧为所选分类的曲目，可添加、编辑曲名作者、拖动排序和移除。固定的“全部曲目”是整个曲库，分类只是引用，同一首可属于多个分类。嵌套目录用 `/`；保持游戏内现有逐层导航与搜索。

添加接受外部 / Project MIDI、文件夹、ZIP 和直接 MIDI/ZIP 下载地址。用户不必先准备生成资产目录。新输入先进入可审阅的草稿行，显示诊断、重复命中及处理状态；选中行才展示源文件和选轨等详情。技术路径、哈希、GUID 和导入预算放进详情或高级区，不占主要流程。

## 原子操作

| 操作 | 改变的对象 | 用户结果 |
| --- | --- | --- |
| 读取输入 | 编辑器草稿 | 枚举 MIDI，预览解析；不改曲库和场景 |
| 添加曲目 | 草稿曲库成员 | 新曲出现在当前分类，同时属于全部曲目 |
| 引用已有曲目 | 草稿分类成员 | 字节哈希与设置一致时复用资产，避免重新生成身份 |
| 修改曲名 / 作者 | 草稿元数据 | 可人工填写；未知作者留空，不从文件名猜成事实 |
| 新建 / 改名 / 排序分类 | 草稿分类 | 层级与顺序变化，歌曲身份不变 |
| 添加到 / 移出分类 | 草稿分类成员 | 不复制歌曲资产，不移除其他分类引用 |
| 从曲库移除 | 草稿全库成员与各分类引用 | 源 MIDI、曲目资产保留；默认曲目跟随修复 |
| 排序 / 倒序 | 草稿全库或分类顺序 | 不重新解析 MIDI |
| 哈希去重 | 草稿引用归并 | 合并 SHA-256 与导入设置均相同的引用，保留源文件 |
| 选用同曲版本 | 明确指定的同标题分组 | 事件数最多优先，再比较源文件时间；不是自动识别音乐作品 |
| 修改选轨 / 排除鼓轨 | 草稿导入设置 | 保存时重新解析该曲，失败保留旧成功数据 |
| 替换源文件 | 草稿替换计划 | 保存时备份原件，预检后原位更新，保留源 GUID 与 songId |
| 清理源文件名 | 显式文件操作 | 通过 AssetDatabase 改名保留 .meta；与显示曲名分离 |
| 保存并应用 | 源资产 → 曲库 → 目标场景的运行数据与菜单 | 只重解析新增 / 改源 / 改设置曲目；提示保存受影响场景 |
| 重新载入 | 编辑器草稿 | 丢弃草稿，读取当前资产；未执行的文件计划随之丢弃 |

保存是以上原子操作的编排，不是重新配置整台播放器；不重建模型、改变音源或 Apply Prefab。文件操作的备份与 Unity Undo 的适用范围分别说明。批次允许逐曲失败，但必须准确显示失败项、已保存项及场景是否应用成功，不能用一个“成功”吞掉同步错误。

## 与之前会话的对应

- 《定位 MIDI 文件导入入口》：加歌后更新目标播放器和菜单。
- 《按 sample、东方和 Arcaea 去重曲目》：源字节哈希去重，源文件保留。
- 《设计类似 VizVid 的收藏夹目录》《添加歌曲分类与搜索》：编辑器分类、多级目录，复用现有运行搜索。
- 《清理文件名并填写作者》《加入曲目并检查音色处理》：显示名与源文件名分离；作者允许为空，能覆盖指定署名。
- 《整理到 uaaaak 并署名改名》：ZIP 批量输入、同曲事件数 / 日期择优、批量署名及分类，替换时保留旧身份与备份。
- 《将 miku 曲库加入游戏子目录》：同内容复用、分类改名及嵌套移动。

黄金角文件通道色、源音轨 / 音色、踏板、力度、表达、完整 MIDI 音高等继续走现有解析与烘焙链；不以编辑器重设计改写播放语义。分发曲库与完整本地曲库继续分开。
