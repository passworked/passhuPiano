# 新乐器资源预算与测量

状态：维护者已确认，2026-11-02。数值的机器可读来源为 [instrument-policy.json](instrument-policy.json)。这是新增乐器的收录硬约束；没有据此改动现有资源，也没有实现自动预算检测器。

## 统计边界

每件乐器按其**完整可见模型与最重的支持配置**统计，包括琴体、键 / 弦 / 琴条、琴弓、踏板、支架及随乐器提供的效果。不能拆分成多个 PR、目录或子对象来分别领取预算。

可互斥的 LOD / 外观按实际允许同时显示的最重组合计算，并说明互斥机制；能同时出现的部分相加。复用资源列明依赖、是否共享以及统计方式。同一路径 / GUID 被多次引用时，音频或纹理只计一次；不同资源副本即使字节相同也不能当作免费。项目共用控制 UI / 字体与世界环境独立列为宿主依赖，不混进新乐器的自有模型。

旧乐器是参考样本，不是新增贡献的自动豁免。缺少数据为 `null` / 未测，不能填写 0。所有记录写明检查的提交、Prefab / 场景对象、配置、工具与日期。

## 硬上限

| 指标 | 上限 | 统计方式 |
| --- | ---: | --- |
| 模型三角面 | 50,000 | 实际渲染三角面，实例按可见数量累计，包含所有可见模型活动部件 |
| 同时使用的不同材质 | 8 | 共享的同一材质计一次；运行时产生的独立材质实例也计入；材质槽 / draw call 另行报告 |
| Renderer | 128 | 乐器专属、可同时启用的 Renderer，包含 Mesh、SkinnedMesh 及专属效果 Renderer |
| 单张纹理尺寸 | 2,048 × 2,048 | 宽、高分别不得超限；不能只检查其中一边 |
| 纹理估算 | 67,108,864 bytes = 64 MiB | RGBA32，包含完整 mip 链；不能用 PNG / JPEG 的磁盘大小代替 |
| 源音频总量 | 33,554,432 bytes = 32 MiB | 实际提交 / 分发的音频文件字节；包含力度层、轮替、奏法、派生根音、音头与循环体 |
| float32 PCM 估算 | 671,088,640 bytes = 640 MiB | 对每个独立 AudioClip 累加 `samples × channels × 4`；samples 是每声道帧数 |
| 全项目物理音源 | 64 个 AudioSource | 共用预算，不是每件乐器各有 64 个 |

几何预算用于模型。粒子还需单列峰值数量、网格复杂度、透明层叠、材质和绘制成本；不能用模型面数达标来证明无限粒子合格。骨骼数、Collider、材质槽、draw calls、运行时分配等目前没有新增统一数值上限，仍需报告相关成本供维护者评审，不应杜撰额外硬上限。

## 纹理怎么算

2D 纹理每层按 RGBA32 计算：

```text
bytes = sum(max(1, floor(width / 2^level))
            × max(1, floor(height / 2^level)) × 4)
```

从原始尺寸累加到 1×1；按完整 mip 链做保守预算，即使本次导入关闭 mip 也使用同一比较口径。数组纹理乘层数，Cubemap 计六个面；3D 纹理每个 mip 还要计对应深度。记录类型、宽高、层 / 面 / 深度和引用数量。

这是约定的保守估算，不是 GPU 驱动分配或客户端 VRAM 实测。实际平台压缩结果可以另外报告，但不靠改用 BC / ASTC 的估计值绕过此项硬上限。生成的图集、法线、遮罩等同样统计，不能只报 Base Color。

## 音频怎么算

源文件总量与 float32 PCM 估算是两项独立硬约束，都要满足。音频格式可由贡献者提议，不固定采样率、声道、压缩格式、力度层数或奏法数；其选择需要维护者审核质量和成本。

PCM 使用导入后的 `AudioClip.samples` 和 `AudioClip.channels`。例如 48 kHz、双声道、10 秒：`480000 × 2 × 4 = 3840000 bytes`，约 3.66 MiB。音头 / 循环体等多个 Clip 各自累计；Streaming 或延迟加载也不能把原始解码规模填成零。

来源压缩量、float32 PCM 估算、Editor 原生内存、真实客户端内存、Unity 构建下载体积和 `.unitypackage` 大小分别报告。float32 估算包含不了所有引擎对象、缓冲及调度开销，不能作为客户端实际总内存结论。当前钢琴的历史参考为源文件约 20.45 MiB、float32 估算约 607.73 MiB，引用的是记录口径，不能据此宣称已经通过客户端性能验收。

每个逻辑音占几条物理源也要记录：现有采样旋律通常 1 条，弦乐音头 / 循环体使用 2 条，鼓组可能预留末尾 16 条；以当前声音池实现为准。新增独立池或增加排队长度不能扩大 64 个共用源的预算。

## 证据与超限

提交统计清单、工具 / 公式、检查对象以及 PC VRChat 单客户端试听与运行结果。实际客户端实验不替代静态资源统计，静态达标也不替代客户端实验。

超限时先精简模型 / 材质 / 纹理 / 音频，或调整设计后重新测量。贡献者和 AI 都不能自行增加限制、改计量单位或以“维护者也许会同意”标记通过；需要改变规则时由维护者明确决定并更新政策。
