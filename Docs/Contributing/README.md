# 提交乐器

状态：**维护者已确认**，2026-11-02。维护者 passhu，GitHub 账号 `passworked`。规则的机器可读版本为 [instrument-policy.json](instrument-policy.json)。本文与它冲突时先报告差异，请维护者裁定，不自行选宽松的一份。

可以直接提交 PR，不必先提 Issue。支持分阶段贡献；模型、音源、接入和文档全部齐备，并由维护者明确验收后，才算正式收录。阶段性 PR 被合并、数据满足预算或自动检查成功，都不等于正式收录。维护者决定是否收录，也决定美术风格、声音质量和音源格式是否适合项目。

仓库目前为私有。贡献者需要维护者安排访问权限；这份指南不授予仓库权限，也不改变仓库可见性。

## 从哪里开始

1. 阅读 [当前实现](../Developer/CURRENT_STATE.md) 和 [AI 工作指南](../Developer/AI_GUIDE.md)，确认自己使用的提交与文档基线。
2. 选择贡献范围：完整乐器、模型、音源、接入代码或文档阶段。可以直接开 PR；想先沟通时也可以提建议。已有关联 PR 时写明依赖和剩余工作。
3. 复制 [提交记录](INSTRUMENT_SUBMISSION_TEMPLATE.md)；需要 AI 或工具处理时，同时使用 [JSON 模板](instrument-submission.template.json)。未测量填 `null` / 未测，不填 0 或“通过”。
4. 按 [资源预算](BUDGETS.md) 测量成本，填写来源、许可、支持能力、接入位置和验证证据。
5. 提交 PR，由 passhu 评审。未完成阶段明确标为阶段提交；申请正式收录时补齐下面的全部项目。

## 接入与兼容

优先复用共享 Facade、Transport、Sequencer、路由、声音池和现有 View。当前代码有六个活动旋律目标和一个停用槽，**没有自动注册任意新乐器的插件接口**。新增目标需要检查数组、位掩码、实时事件编码、GM 排序、哈希、UI、本地化及保存 / 恢复；详见 [追加接入矩阵](../UdonMidiPlayer/18-adding-instruments.md)。

保留命名空间、程序集、GUID、`.meta`、songId 与未涉及内容。主场景、练习系统和两份分发 Prefab 是独立目标，PR 必须声明改哪一个；不默认同步曲库或 Apply 场景覆盖。涉及公共状态 / 恢复时明确列出影响和多人验证缺口，由维护者判断额外验收范围。

美术表现围绕实际乐器部件、演奏动作和可辨认的发声反馈设计。现有高亮、轻量粒子与暂停 / 停止 / 定位生命周期应保持一致；不要求所有乐器具备相同动画、瀑布或物理输入方式。

## 正式收录的完成条件

- 模型、可用音源、实际接入与使用 / 维护说明齐全；所有依赖可获取且许可可分发。
- 所有硬上限满足，统计覆盖声明的最重配置；提交数据与检查对象属于同一版本。
- MIDI 文件播放在 PC VRChat 中实际运行，提交客户端版本、世界 / 提交版本、设备、步骤、结果与试听证据。其他输入按声明验证，未验证保留原样。
- PC 上至少记录开始 / 停止、切曲、暂停 / 恢复、定位、释放 / 踏板（如适用）、高低音域、声音与模型对应关系。模型实体范围外不假装存在相应可动部件。
- 同步、旧数据迁移、硬件设备或移动端改动另列验证结果及缺口；单客户端通过不能写成双客户端通过。
- 由维护者明确确认收录状态。模板、JSON 与文档不构成自动验收或已经启用的 CI / 分支保护。
