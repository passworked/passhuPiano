# 在 Unity 中导入和管理 MIDI

适用于 `1.0.0-rc.3`。本教程面向已安装播放器的世界作者；工程安装见 [GETTING_STARTED](GETTING_STARTED.md)。使用原有主场景或自己的世界，不需要新建替代场景。导入和整理曲库请退出 Play Mode。

## 第一次加歌

1. 在 Hierarchy 选中你要加歌的播放器，打开 **Tools → Music MIDI Player → Import MIDI**（**Edit Library** 是同一个窗口）。也可在曲库 Inspector 或 Configure Player 中点 **编辑 MIDI 曲库 / Edit MIDI library**。
2. 核对顶部曲库。窗口优先使用选中播放器的曲库；多个播放器曲库不同时，明确选择目标。更换了播放器选择时，点 **使用选中的播放器**。尚未配置播放器时先通过 Configure Player 应用曲库与音源。
3. 左侧选择分类，或点 **全部曲目**。点击左侧 `+` 新建分类，例如 `游戏音乐/uaaaak`；`/` 表示子分类。
4. 把电脑中的 `.mid`、`.midi`、文件夹或 `.zip` 拖到右侧提示区。右侧 `+` 也能选文件、文件夹、Project 选中资源或下载直链。无需先手工复制进 Assets。一次拖入多个文件即可批量添加。
5. 曲目以草稿行出现，后台逐首读取。直接修改曲名和作者；作者未知就留空。点击曲目可查看时长、音轨和诊断。默认保留全部音轨、通道 10 与 MIDI 0～127 的音高。
6. 点击 **保存并应用 / Save and apply**。工具复制需要的外部 MIDI、生成或复用歌曲资产、保存曲库，并更新已打开场景中使用该曲库的播放器和菜单。查看底部结果，再用 **Ctrl+S 保存受影响场景**。

看到“没有使用此曲库的播放器”时，歌曲和曲库已保存，但没有应用到场景。打开目标场景，选对曲库并再次保存应用，或在 Configure Player 中首次配置。修改源曲库引用本身不等于已更新运行数据。

## 像编辑歌单一样整理

| 想做什么 | 操作 |
| --- | --- |
| 修改曲名、作者 | 直接编辑曲目行的两列；最后保存并应用 |
| 批量署名 | 勾选多首曲目，填写作者，点“批量填写作者” |
| 查询作者 | 选中曲目点“查找作者”，用 Chrome 打开搜索；核实后人工填写，工具不自动把搜索结果当成署名 |
| 调整歌曲顺序 | 拖动行左边的把手；“更多 → 倒序”也可反转当前列表 |
| 搜索 | 搜索曲名、作者或分类；清空搜索后恢复分类列表；搜索时禁用拖动排序 |
| 放入分类 | 勾选曲目，点“加入分类”；同一首可在多个分类出现 |
| 移动分类 | 在来源分类中选择曲目，再点“移到分类”；仅移出当前分类，其他收藏保留 |
| 从分类移除 | 在分类内选中曲目，点右侧 `−`；仍保留在全部曲目和其他分类 |
| 从曲库移除 | 在“全部曲目”中选中并点 `−`；保留源 MIDI 和歌曲资产，不删磁盘文件 |
| 修改分类层级 | 选中分类，编辑底部路径；改名时其子分类一同迁移 |
| 删除分类 | 选中分类，点左侧 `−`；保留歌曲，子分类仍可独立存在 |
| 设默认曲目 | 选中歌曲，在详情中点“默认曲目” |
| 放弃尚未保存的修改 | 点“重新载入 / Reload”；尚未执行的导入、替换和改名计划一起丢弃 |

拖动分类把手改变分类顺序。游戏内目录沿用已有逐层进入 / 返回及搜索，不增加玩家在世界内编辑曲库的权限。

## 重复文件和同曲不同版本

**完全相同的 MIDI**：新增时按 SHA-256 与导入选轨设置复用已有歌曲，保留 songId 和已确认的署名。仅文件名相同不会被视为同一源。整理已经存在的重复曲目时，用 **更多 → 合并相同 MIDI**：合并分类引用和默认曲目，原文件与资产保留。

**同曲不同版本**：默认分别保留。需要沿用此前“事件最多优先、相同事件数选最新”的规则时，先把同一作品各版本的显示曲名改成一致，再在“更多”或“导入设置”启用 **同名择优：事件最多，其次最新**，保存时执行。统计源 MIDI 的全部事件，而不只是音符数；时间取源文件修改时间，ZIP 取条目时间。工具不会识别旋律来猜两首作品是否相同。完整版、游戏版、简化版想分别保留时，使用不同显示名或关闭此规则。

若分组已有曲目，优选的新版本作为替换计划接到旧身份上；替换前备份原件，其他分类引用继续指向原 songId。Downloads 中的原始输入与 ZIP 不删除。

## 源文件维护

- **重新解析 / Reimport**：原 MIDI 被编辑后，选中曲目执行，再保存。修改选轨或“排除通道 10 打击乐”也会在保存时重解析该曲。原始轨号从 0 开始；被过滤轨道的全局 tempo 和现有音色元数据保留规则沿用解析器。
- **替换 MIDI**：在曲目详情选择新 MIDI，再保存。先解析新文件，再备份并原位替换旧源；保留源 GUID、歌曲 GUID 与 songId。解析失败时不写坏原源文件。备份在工程根 `RecoveryBackups/MidiSourceReplacement/`。
- **整理文件名**：打开“源文件详情”，填写“保存时修改源文件名”，或点“按曲名清理文件名”。它与显示曲名分开，通过 Unity 的 AssetDatabase 改名，保留 `.meta`；同一源的其他歌曲资产会更新来源路径。不要在资源管理器中单独删除 `.meta`。
- **批量整理文件名**：勾选多首曲目，使用“更多 → 按曲名批量整理文件名”；先核对显示曲名，保存时执行。
- **批量重新解析**：勾选曲目，使用“更多 → 重导入选中的曲目资产”，再保存应用。
- **来源地址下载**：右侧 `+ → 从链接下载`，接受直接 `.mid`、`.midi` 或 `.zip` HTTP(S) 链接。普通网页、需要登录的页面、MuseScore 页面或 YouTube 不是 MIDI 直链；先用自己的下载流程取得文件再拖入。单次输入上限 64 MiB，ZIP 最多 4096 个 MIDI 条目，解压 MIDI 总量最多 64 MiB。

来源维护的计划随草稿保存；实际文件写入、备份和改名不能靠 Unity Undo 还原。分类和草稿元数据支持 Undo。若一个源文件被多个不同选轨资产共用，替换后也应重新解析其他引用该源的资产，再应用相关曲库。

## JSON 与高级设置

**更多 → 导出全部 JSON / 导出当前分类 JSON / 从 JSON 载入** 用于备份和迁移歌单引用、顺序、默认曲目及分类结构。先保存后导出。JSON 不是 MIDI 文件包；接收工程须已有相同 GUID/songId 的歌曲资产和源文件，缺失依赖时明确报错，不悄悄创建占位歌曲。复制工程或分享资源时保留对应 `.meta`。

通常无需修改 **更多 → 导入设置**：外部源默认复制到 `Assets/music/Imported`，歌曲资产默认生成到 `Assets/UdonMidiPlayer/Editor/Generated/Songs`。可以启用“保留导入目录层级”，把文件夹 / ZIP 的层级带入当前分类下面。

## 失败时如何处理

| 结果 | 下一步 |
| --- | --- |
| 曲目行显示失败 | 选中查看完整诊断，修复文件或设置后再保存；其他成功歌曲可能已保存 |
| 有歌曲导入失败 | 整批不会应用到场景；修复失败项或从草稿移除后重试 |
| 曲库保存成功，场景应用失败 | 保留已保存曲库，按底部具体错误修复接线 / 默认曲目 / 音源，再保存应用；不要 Apply 整个 Prefab 覆盖 |
| 提示其他位置已修改曲库 / 歌曲 | 重新载入后再编辑，避免覆盖并行修改 |
| 不支持 Type 2 / SMPTE 或损坏文件 | 在 MIDI 编辑软件中转换为 SMF Type 0/1、PPQ，再导入 |

日常加歌只更新已加载的普通场景实例；独立练习场景、未打开场景、两份分发 Prefab 和 Prefab 编辑模式不会自动同步。库、音源初次接入仍使用 Configure Player。

编辑器导入成功不等于真实 VRChat 听音或多人同步验收。rc.3 的发布说明会分别记录本次 Editor 检查与尚未执行的客户端验证。发布到仓库的谱面仍须满足项目许可白名单，本地导入不改变其授权。
